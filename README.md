# Integrated Hostel Management System (IHMS) — Production Enterprise ERP

A complete, production-ready, multi-tenant Enterprise Resource Planning (ERP) platform for large-scale student hostel chains and university housing organizations, backed by **MongoDB (NoSQL)**, **Node.js / Express / NestJS Architecture**, **Next.js 14 / React / TypeScript / Tailwind CSS**, and **Socket.IO Real-Time WebSockets**.

---

## 1. Technology Stack

- **Frontend**: Next.js 14, React 18, TypeScript, Tailwind CSS, Lucide Icons, Recharts, Socket.IO Client.
- **Backend**: Node.js, TypeScript, Mongoose ODM, Socket.IO Gateway, Passport JWT, Bcrypt, Class-Validator, Express.
- **Database**: MongoDB Atlas / NoSQL document modeling with compound tenant indexes, aggregation pipelines, and atomic counters.
- **Real-Time Pipeline**: WebSockets / Socket.IO with rooms segregated by `org:<orgId>`, `branch:<branchId>`, and `user:<userId>`.
- **Security & RBAC**: Multi-tenant isolation guards (`TenantGuard`, `RolesGuard`, `JwtAuthGuard`), 13 RBAC roles, Bcrypt password hashing, Helmet security headers.

## 3. Quick Start & Execution Guide

### Prerequisites
- Node.js 18+ or 20+ installed
- npm 9+ or 10+ installed

### Step 1: Install Dependencies
From the root workspace directory:
```bash
npm install
```

### Step 2: Seed the Database
Run the seed script to populate realistic multi-branch demo data, rooms, beds, students, fee demands, receipts, and P&L entries:
```bash
npm run seed
```

### Step 3: Run Backend API & Real-Time Socket Server
```bash
npm run dev:backend
```
Backend API will start at: `http://localhost:5000` (Socket.IO Gateway on `/socket.io`).

### Step 4: Run Next.js Frontend Dashboard
In a separate terminal:
```bash
npm run dev:frontend
```
Frontend will be live at: `http://localhost:3000`.

## 4. Connecting to MongoDB Atlas (Production)

To connect to your live MongoDB Atlas cloud cluster:
1. Open `.env` (or `backend/.env`).
2. Set your MongoDB Atlas connection string:
   ```env
   MONGODB_URI=mongodb+srv://<username>:<password>@cluster0.mongodb.net/ihms_db?retryWrites=true&w=majority
   ```
3. Restart the backend server. IHMS will automatically connect to your Atlas cluster.
*(Note: In local development, if `MONGODB_URI` is left blank, IHMS automatically starts an embedded in-process MongoDB NoSQL engine).*

## 5. Permanent Business Identifier Architecture

- **Hostel Branch**: `HYD001`, `HYD002`

## 6. Real-Time Socket.IO Event Engine

| Event Name | Emitted When | Target Rooms | Payload |
| :--- | :--- | :--- | :--- |
| `bed.status_changed` | Bed marked Occupied / Available / Maintenance | `branch:<id>` | `bedId`, `bedCode`, `status` |
| `payment.completed` | Accountant / Student records a fee payment | `org:<id>`, `branch:<id>` | `receiptNumber`, `customerCode`, `amount`, `balance` |
| `student.admitted` | New student admitted and assigned bed | `branch:<id>` | `studentId`, `customerCode`, `name` |
| `student.transferred`| Student transferred across branches | `org:<id>` | `studentId`, `customerCode`, `targetBranchId` |
| `complaint.created` | Maintenance issue logged | `branch:<id>` | `complaintNumber`, `category`, `roomCode` |
| `complaint.resolved`| Staff resolves complaint with cost | `branch:<id>` | `complaintNumber`, `status` |
| `leave.created` | Student submits leave application | `branch:<id>` | `leaveNumber`, `studentName` |
| `leave.status_changed`| Warden approves/rejects leave | `branch:<id>` | `leaveNumber`, `status`, `gatePassCode` |
| `visitor.checked_in`| Security registers visitor | `branch:<id>` | `visitorPassNumber`, `studentName` |
| `dashboard.kpi_updated`| Any state mutation occurs | `org:<id>` | Triggers instant real-time KPI re-aggregation |
